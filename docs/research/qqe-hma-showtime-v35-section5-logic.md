## 2. QQEの計算ロジック

### 2.1 QQEとは何か？

**QQE（Quantitative Qualitative Estimation）** は、RSI（相対力指数）を2段階でスムージングし、さらにATR（平均真の範囲）でバンドを形成することで、**トレンドの質的・量的評価**を行う指標です。

### 2.2 計算の全体フロー

```
価格データ
   ↓
[Step 1] RSI計算（期間14）
   ↓
[Step 2] RSIをEMAスムージング（SF=5）
   ↓
[Step 3] スムージング後のRSIの変動幅（ATR）を計算
   ↓
[Step 4] ATRをさらにEMAスムージング
   ↓
[Step 5] QQEファクターを掛けてバンド幅を決定
   ↓
[Step 6] ロングバンド・ショートバンドを形成
   ↓
[Step 7] RSIとバンドのクロスでトレンド判定
```

### 2.3 Step-by-Step 詳細解説

#### **Step 1: RSI計算**

```pine
RSI_Period = 14  // デフォルト設定
Rsi = ta.rsi(close, RSI_Period)
```

**RSIの意味:**
- 0-100の範囲で価格の強弱を示す
- 50以上 = 買い優勢
- 50以下 = 売り優勢

**なぜRSIを使うのか？**
- 価格の絶対値ではなく「強弱の変化」を捉えられる
- 銘柄によらず0-100の統一スケール

---

#### **Step 2: RSIをEMAスムージング**

```pine
SF = 5  // スムージングファクター
RsiMa = ta.ema(Rsi, SF)
```

**スムージングの効果:**
- ノイズ（短期的な上下動）を除去
- トレンドの本質を抽出
- ダマシシグナルを減少

**📊 画像が欲しい箇所①:**
> RSI（生データ）とRsiMa（スムージング後）の比較チャート

---

#### **Step 3: RSIの変動幅（ATR）を計算**

```pine
Wilders_Period = RSI_Period * 2 - 1  // 14 * 2 - 1 = 27
AtrRsi = math.abs(RsiMa[1] - RsiMa)  // 1本前との差分の絶対値
MaAtrRsi = ta.ema(AtrRsi, Wilders_Period)
```

**変動幅の意味:**
- RSIがどれくらい激しく動いているか
- 変動が大きい = トレンドが強い
- 変動が小さい = レンジ相場

---

#### **Step 4: QQEファクター適用**

```pine
// 銘柄別の最適化（自動判定）
final_qqe_factor = get_qqe_factor()

// BTC: 12.0
// ETH: 10.0
// USDJPY: 4.238
// その他FX: 4.238

dar = ta.ema(MaAtrRsi, Wilders_Period) * final_qqe_factor
```

**QQEファクターの役割:**
- バンド幅を調整（大きいほどバンドが広い）
- 銘柄のボラティリティに合わせて最適化
- BTCは変動が激しいので大きめ（12.0）
- FXは比較的安定しているので小さめ（4.238）

**なぜ銘柄別に変える必要があるのか？**
- BTC: 1分で数万円動く → バンドを広くしないとダマシ多発
- USDJPY: 1分で数銭程度 → 狭いバンドで十分

---

#### **Step 5-6: ロングバンド・ショートバンド形成**

```pine
var float longband = na
var float shortband = na

newlongband = RSIndex - dar  // RSIの下側
newshortband = RSIndex + dar  // RSIの上側

// バンドの更新ロジック（トレーリング）
longband := RSIndex[1] > longband[1] and RSIndex > longband[1]
            ? math.max(longband[1], newlongband)
            : newlongband

shortband := RSIndex[1] < shortband[1] and RSIndex < shortband[1]
             ? math.min(shortband[1], newshortband)
             : newshortband
```

**バンドの動き:**
- **ロングバンド（下側）**: 上昇トレンドでRSIを下から支える
- **ショートバンド（上側）**: 下降トレンドでRSIを上から抑える
- バンドは一方向にしか動かない（トレーリング）

**📊 画像が欲しい箇所②:**
> RSI、ロングバンド、ショートバンドの3本を表示したチャート

---

#### **Step 7: トレンド判定**

```pine
cross_1 = ta.cross(longband[1], RSIndex)  // RSIがロングバンドを下抜け
trend := ta.cross(RSIndex, shortband[1]) ? 1    // 買いトレンド開始
         : cross_1 ? -1                         // 売りトレンド開始
         : nz(trend[1], 1)                      // 前回のトレンド継続

FastAtrRsiTL = trend == 1 ? longband : shortband
```

**シグナル発生条件:**
- RSIがショートバンドを**上抜け** → **買いシグナル**
- RSIがロングバンドを**下抜け** → **売りシグナル**

**QQEの強み:**
- 単純なRSIのクロスより遅延が少ない
- バンドがトレーリングするのでダマシに強い
- トレンドの「質」まで評価できる

---

### 2.4 QQE最終シグナル

```pine
var int QQExlong = 0
var int QQExshort = 0

QQExlong := FastAtrRsiTL < RSIndex ? QQExlong + 1 : 0
QQExshort := FastAtrRsiTL > RSIndex ? QQExshort + 1 : 0

// シグナル発生（カウンターが1になった瞬間）
qqe_long = QQExlong == 1
qqe_short = QQExshort == 1
```

**カウンター方式の利点:**
- シグナル発生は「瞬間」だけ（1本のバーのみ）
- 重複エントリーを防ぐ
- バックテストで正確な検証が可能

## 3. HMAの計算と活用

### 3.1 HMAとは何か？

**HMA（Hull Moving Average）** は、通常の移動平均線（SMA/EMA）の**遅延を大幅に削減**しつつ、**スムーズさを維持**する革新的な指標です。

開発者: Alan Hull（オーストラリアのトレーダー）

### 3.2 通常のMAとの違い

**SMA（単純移動平均）:**
- 計算が簡単
- 遅延が大きい（トレンド転換に遅れる）
- スムーズ

**EMA（指数移動平均）:**
- 直近のデータを重視
- SMAよりは遅延が少ない
- やや荒い

**HMA（ハル移動平均）:**
- **遅延が最小**（トレンド転換を素早く捉える）
- **スムーズ**（ノイズが少ない）
- 計算がやや複雑

### 3.3 HMAの計算式

```pine
hma_calc(src, length) =>
    wma1 = ta.wma(src, length / 2)      // 半分の期間でWMA
    wma2 = ta.wma(src, length)           // 通常の期間でWMA
    ta.wma(2 * wma1 - wma2, math.round(math.sqrt(length)))  // 差分をさらにWMA
```

**計算の流れ:**

```
価格データ（close）
   ↓
[Step 1] WMA（期間 length/2）→ wma1
   ↓
[Step 2] WMA（期間 length）→ wma2
   ↓
[Step 3] 2 * wma1 - wma2（加重された差分）
   ↓
[Step 4] その差分をWMA（期間 √length）でスムージング
   ↓
HMA完成
```

**📊 画像が欲しい箇所③:**
> SMA、EMA、HMAの3本を同時表示した比較チャート（遅延の違いが一目瞭然）

### 3.4 QQE v3.5でのHMA活用法

```pine
hma_length = 9  // デフォルト設定
hma = hma_calc(close, hma_length)
hma_prev = hma[1]

// シグナル判定
hma_long = ta.crossover(hma, hma_prev) and close > hma
hma_short = ta.crossunder(hma, hma_prev) and close < hma

// トレンド判定（フィルター用）
hma_trend = close > hma
```

**HMAの役割（QQE v3.5での位置づけ）:**
1. **QQEシグナルの確認フィルター**
   - QQEが買いシグナル → HMAも上向き → 信頼度UP
   - QQEが買いシグナル → HMAは下向き → 見送り

2. **短期モメンタムの確認**
   - HMAがクロスアップ → 短期的な上昇モメンタム
   - HMAがクロスダウン → 短期的な下降モメンタム

3. **エントリータイミングの最適化**
   - QQEは「方向」を決定
   - HMAは「タイミング」を決定

**なぜ期間9なのか？**
- 1秒足での検証結果から最適化
- 9未満 → ノイズが多い
- 9超 → 遅延が増える
- 9 → ちょうど良いバランス

## 4. AIスコアの4要素と重み付け

### 4.1 AIスコアの設計思想

**目的:**
> シグナルの「信頼度」を0-100点で可視化し、エントリー判断の材料を提供

**従来の問題:**
- シグナルが出ても「強いのか弱いのか」わからない
- 同じシグナルでも勝率に差がある
- 主観的な判断になりがち

**AIスコアの解決策:**
- 4つの要素を**定量的に評価**
- 合計100点満点でスコア化
- 70点以上 = 強気シグナル（エントリー推奨）
- 60-70点 = 中立的（慎重に）
- 60点未満 = 弱気シグナル（見送り推奨）

### 4.2 AIスコアの4要素

```
AIスコア = 信号 + QQE強度 + Vol + 出来高 + 基礎点
          (0-25) (10-20)   (-10~15) (-5~10)  (20)

最小: 0点（全要素が最低）
最大: 100点（全要素が最高）
```

#### **要素1: シグナルの有無（0 or 25点）**

```pine
signal_base_score := (qqe_long or qqe_short or hma_long or hma_short)
                     ? 25 : 0
```

**意味:**
- QQEまたはHMAのいずれかがシグナル発生 → 25点
- シグナルなし → 0点

**なぜ25点？**
- 全体の1/4（25%）をシグナルの有無に割り当て
- シグナルがないと他の要素が高くても意味がない

---

#### **要素2: QQE強度（10-20点）**

```pine
qqe_distance = math.abs(RSIndex - 50)  // RSIの50からの距離

qqe_strength_score := qqe_distance > 20 ? 20   // 強い（過買い/過売り）
                      : qqe_distance > 10 ? 15  // 中程度
                      : 10                      // 弱い（中立付近）
```

**意味:**
- RSIが50から遠い → トレンドが強い → 高得点
- RSIが50に近い → トレンドが弱い → 低得点

**具体例:**
- RSI = 70（距離20）→ 20点（強い買いトレンド）
- RSI = 60（距離10）→ 15点（中程度）
- RSI = 52（距離2）→ 10点（弱い）

**📊 画像が欲しい箇所④:**
> RSIの値とQQE強度スコアの関係を示す図（50を中心に離れるほど高得点）

---

#### **要素3: ボラティリティ（-10～+15点）**

```pine
atr_current = atr_value
atr_avg = ta.sma(atr_current, 20)
atr_ratio = atr_current / atr_avg

vol_score_value := atr_ratio > 1.1 and atr_ratio < 2.0 ? 15   // 理想的
                   : atr_ratio < 0.8 ? -10                     // 低すぎる（減点）
                   : 5                                         // 普通
```

**意味:**
- ATRが平均の1.1~2.0倍 → **適度なボラティリティ** → 15点
- ATRが平均の0.8倍未満 → **動きが鈍い** → -10点（減点）
- それ以外 → 5点

**なぜボラティリティが重要？**
- 動きが大きい = 利幅が取れる
- 動きが小さい = スプレッド負けのリスク
- ただし、大きすぎる（2.0倍超）= 異常値・急変 → 危険

**具体例:**
- ATR = 15、平均 = 10 → 比率1.5 → **15点（理想的！）**
- ATR = 10、平均 = 10 → 比率1.0 → 5点（普通）
- ATR = 7、平均 = 10 → 比率0.7 → **-10点（動きが鈍い）**

---

#### **要素4: 出来高（-5～+10点）**

```pine
volume_avg = ta.sma(volume, 20)
volume_ratio = volume / volume_avg

vol_confirm_score := volume_ratio > 1.2 ? 10   // 出来高が多い（信頼度UP）
                     : volume_ratio < 0.8 ? -5  // 出来高が少ない（減点）
                     : 0                        // 普通
```

**意味:**
- 出来高が平均の1.2倍以上 → **参加者が多い** → 10点
- 出来高が平均の0.8倍未満 → **参加者が少ない** → -5点（減点）
- それ以外 → 0点

**なぜ出来高が重要？**
- 出来高が多い = トレンドの信頼性が高い
- 出来高が少ない = ダマシの可能性が高い

---

#### **要素5: 基礎点（固定20点）**

```pine
raw_score = signal_base_score + qqe_strength_score + vol_score_value + vol_confirm_score + 20
```

**なぜ基礎点が必要？**
- 最低点を0点にしない（全ての要素が最低でも20点は保証）
- スコアの分布を調整（40-90点の範囲に収める）

---

### 5.3 上位時間足フィルター（MTF）

```pine
show_mtf = true  // デフォルトで有効
higher_tf = "1"  // 1分足（1秒足の60倍）

htf_close = request.security(syminfo.tickerid, higher_tf, close, ...)
htf_hma = request.security(syminfo.tickerid, higher_tf, hma_calc(close, hma_length), ...)
htf_trend = htf_close > htf_hma
```

**MTFの役割:**
- 上位時間足のトレンドを確認
- 上位足と同方向のみエントリー
- 逆張りを防ぐ

**具体例（1秒足で取引する場合）:**
- 1分足（60秒足）のHMAが上向き → 買いのみ
- 1分足のHMAが下向き → 売りのみ

**📊 画像が欲しい箇所⑥:**
> 1秒足と1分足を並べて表示し、MTFフィルターの効果を示す図

## 6. イグジットロジックの詳細

### 6.1 イグジットの3つのトリガー

QQE v3.5では、以下の3つのいずれかでイグジット（決済）します:

#### **トリガー1: 利確ライン到達**

```pine
profit_target = entry_price + (atr_value * target_atr_multi)  // 買いの場合
stop_loss = entry_price - (atr_value * stop_atr_multi)

should_exit = close >= profit_target  // 利確
```

**ATR倍率の意味:**
- `target_atr_multi = 1.0` → ATRの1倍で利確
- `stop_atr_multi = 1.0` → ATRの1倍で損切り
- **リスクリワード比 1:1**

**なぜATRを使うのか？**
- 銘柄のボラティリティに自動対応
- BTCなら数百円、USDJPYなら数pips等、最適な幅に

**具体例（BTC、ATR=500円の場合）:**
- エントリー: 96,000円
- 利確ライン: 96,500円（+500円）
- 損切りライン: 95,500円（-500円）

---

#### **トリガー2: 損切りライン到達**

```pine
should_exit = close <= stop_loss  // 損切り（買いの場合）
```

**損切りの重要性:**
- 1回の負けを限定
- 資金を守る最重要ロジック
- **損切りなしの運用は絶対NG**

---

#### **トリガー3: 反対シグナル発生**

```pine
should_exit = entry_short  // 買いポジション保有中に売りシグナル
```

**なぜ反対シグナルで決済？**
- トレンドが反転した可能性
- 利確・損切りを待たず早めに逃げる
- 損失拡大を防ぐ

**📊 実際のチャート例（利確・損切り・反対シグナルの3パターン）:**

### 6.2 決済後の処理

```pine
if should_exit
    exit_pnl = current_pnl  // 損益を確定
    daily_pnl += exit_pnl    // 日次損益に加算

    max_daily_pnl := math.max(max_daily_pnl, daily_pnl)  // 最高記録更新

    if exit_pnl > 0  // 勝ち
        win_count += 1
        win_streak += 1  // 連勝カウンター
        max_win_streak := math.max(max_win_streak, win_streak)
    else  // 負け
        loss_count += 1
        win_streak := 0  // 連勝リセット

    entry_direction := 0  // ポジション解消
    entry_price := na
```

**記録する項目:**
- 日次損益
- 勝敗カウント
- 連勝記録
- 最高損益記録

## 7. 1秒足採用の技術的根拠

### 7.1 なぜ1秒足なのか？

**従来の常識:**
> 「短期足はノイズが多くて使えない」

**QQE v3.5の挑戦:**
> 「QQE + HMA + AIスコアの3重フィルターならノイズを除去できる」

### 7.2 1秒足のメリット

#### **メリット1: チャンス増加**
- 1分足: 1日1440本 → シグナル10-30回
- 1秒足: 1日86,400本 → シグナル100-500回
- **約10-20倍のチャンス**

#### **メリット2: 資金効率の向上**
- ポジション保有時間が短い（平均5-60秒）
- 同じ資金で1日に何度も回転
- 複利効果が加速

#### **メリット3: リスクの分散**
- 1回あたりの損益が小さい
- 大きな負けが少ない
- 統計的に安定

#### **メリット4: エンタメ性**
- 配信が動的で飽きない
- リアルタイムの緊張感
- 視聴者が見ていて楽しい

---

### 7.3 1秒足のデメリットと対策

#### **デメリット1: ノイズが多い**

**対策:**
- QQE（スムージング済み）
- HMA（遅延が少ない）
- AIスコア（信頼度フィルター）
- → **3重フィルターでノイズ除去**

#### **デメリット2: スプレッド負け**

**対策:**
- スプレッドが狭い銘柄を選択（BTC、USDJPY等）
- 利確幅をATR倍率で調整（スプレッド以上確保）
- Bybit等の低スプレッド取引所を使用

#### **デメリット3: サーバー負荷**

**対策:**
- TradingViewは1秒足対応
- Pine Scriptは軽量設計
- バックテストで事前検証

#### **デメリット4: 感情的になりやすい**

**対策:**
- 完全自動化（API連携で感情排除）
- 損切り・利確を自動実行
- 日次リセット機能（感情リセット）
